## 1. 做了什么

- `hearth` 叫「柴炉」，`stove` 叫「料理台」（id 不变）。烧水、喝水、泡茶挪到柴炉；做饭、收拾鱼和带回来的东西还在料理台；提水的桶照旧放在料理台边。接水管最后一阶段的字改成「料理台边能出水了」。
- 野外饭点没带干粮不算缺餐，从 `IMPL` 挪到 `CONFIG.outing.mealWithoutRationsIsMissed`，注释指向 02 第 9.4 节。代码里指向 02 的节号都对过一遍，没有对不上的。
- 镜头换成四间。新模块 `game/src/core/rooms.ts` 直接读 `assets/05/rooms/g5_20261115/room_locations.json`：哪个地点在哪间、窗、门洞、展示位、灯、站位都从这份 JSON 来，`cameras.ts` 删掉了。测试核对 JSON 的地点 id 和内核一致、各间的东西和 03 第 3.1 节的表一致、默认是观测间。
- 地窖口挪到院子（03 第 3.2 节、JSON 都这么写）。
- 灰盒画面一次只画选中的那一间，用 JSON 的 2560 坐标平滑缩放到 960×540、320×180、480×270。选房间的按钮在画面下面，默认观测间，不跟人；他在哪间，那间的按钮后面带个点。
- 不出门、不做项目的长跑数值和改动前逐行相同。改名和烧水挪地方对长跑没有影响；变了的只有做修缮的几种情形，全是地窖挪到院子带来的（见 R1）。

## 3. 各间看得见他（给 04、05）

重跑：`cd game && node tools/report.ts --runs 40 --days 60`。40 个种子 × 入冬起 60 个游戏日，正常陪伴、不出门、不专注，他照自己的习惯做项目。这是「选了这一间时，醒着的时间里画面上有人」的比例，不是镜头裁切的假设了。

| 房间 | 占醒着的时间 | 包括的地点 |
|---|---|---|
| 炉间 | 35.1% | 柴炉、柴堆、扶手椅、收音机、唱片机 |
| 观测间 | 25.0% | 雪窗、窗台、书桌、书架、仪器角 |
| 灶间 | 16.0% | 料理台、储物架、工作台、门和衣架、后门 |
| 卧室 | 0.5% | 床 |
| 四间都不在 | 23.4% | 院子、林子边缘和溪湾、泉屋和防风林 |

| 季节 | 炉间 | 观测间 | 灶间 | 卧室 |
|---|---|---|---|---|
| 冬 | 34.1% | 23.7% | 18.1% | 0.5% |
| 春 | 33.5% | 21.4% | 16.6% | 0.5% |
| 夏 | 37.9% | 31.4% | 14.3% | 0.5% |
| 秋 | 36.0% | 24.6% | 13.1% | 0.5% |

- 默认的观测间，醒着的时间里大约四分之一看得见他，主要是书桌（13.7%）和看雪。扶手椅一处就占 26.2%，所以炉间最常有人。
- 卧室醒着几乎没人（只有起床那几分钟）；他睡着的那三分之一时间都在卧室，不算在这张表里。
- 这些比例是 04 设计「空屋时画面上给什么提示」的依据。我不改默认房间，只是把数给出来。

## 4. 给 GPT：适配器要跟着换的

`Snapshot` 改了这些，`设计/原型/05_v1.0_G2只读视觉适配器.js` 读的镜头键已经没有了：
