# 系统通知实现（04 A7）

> 2026-11-17，Claude。对应 04 第 19.2、20.3 节的 A7：「独立设置『专注/休息结束时系统通知』，默认关闭。启用并授权后每次结束最多一条，只报告现实计时，不附带游戏内容、份数与样式；权限不可用时安静退化为界面状态更新。」只动了灰盒的 app 层，内核没改。

## 1. 做了什么

- `game/src/app/notify.ts`：上半是纯函数（什么时候发、发什么字、去重），下半是浏览器那一层（本机设置、问权限、`new Notification`）。
- `runtime.ts`：主窗口每次心跳推进以前记下这一轮的计时，推进以后把内核吐出的结束事件交给通知器。只有主窗口在推进，所以只有主窗口会发。
- `main.ts`：专注条「自动接下一轮」旁边加了一个勾选框「专注/休息结束时系统通知」，后面一句现在的情况（只在开着的时候出现）。
- `tests/notify.test.ts` 13 条；`tools/notify-smoke.mjs` 是无界面 Chrome 的真浏览器冒烟。

## 2. 先选的做法（等用户定）

| # | 做法 | 理由 | 另一种 |
|---|---|---|---|
| N1 | 设置存成**本机设置**（`localStorage` 的 `bts.prefs.v1`），不进存档；删档重开不丢 | 06 第 2 节把通知设置放在 UIState；权限本来就跟着浏览器走，换个浏览器或以后换桌面壳都得重新授权 | 存进存档的 `focus.settings.notify`。内核里已经有这个字段（默认 false），但没有命令能改它；这次没动内核，它现在没人用。以后要么删掉，要么加一条 `cmdSetNotify` 改用它 |
| N2 | **只在计时自己走完时发**：专注到点、休息到点。你自己点「结束」「跳过休息」不发，正向计时没有终点也不发 | 你按的你知道，不用再告诉你 | 也给提前结束发一条 |
| N3 | 文字：标题「25 分钟专注结束」「5 分钟休息结束」；正文只有「接下来休息 5 分钟」「下一轮 25 分钟已开始」或空着。分钟数是这一轮计时器的长度（含「加 5 分钟」，暂停的那段不算） | 只说现实计时。不写份、样式、屋里的事，也不写「他」 | 标题用应用名、正文写时长 |
| N4 | **只在你勾上开关的那一下问一次权限**；浏览器已经有答案（允许或拒绝）就不问。没允许时勾选框保持勾着，后面写「浏览器没有允许通知，只在计时区显示」，计时区照常变；以后你在浏览器设置里放开了，不用重勾就开始发 | 不反复弹请求；你的选择留着，不替你取消 | 被拒就把勾去掉 |
| N5 | 你关了询问框没答（权限还是「未决定」）：不再自己问，那一句提示「取消再勾一次可以重新询问」 | 再问一次也是你点出来的 | 每次开应用问一次（不做，违背「不反复弹」） |
| N6 | 多窗口：只有拿着锁的主窗口发；另外每条带一个标签（这一轮的记录号加开始时刻加 focus/break），本机所有窗口共用「上一条的标签」，主窗口换人时同一个终点不会再发一次；系统也按标签替换 | 主窗口发完就关、接手的窗口从旧一点的状态再走到同一个终点，是唯一能重发的路 | — |
| N7 | 不处理点通知；不设 `requireInteraction`（会自己收进通知中心）；声音用系统默认 | 不把人拉回游戏，不抢注意力 | 点了把游戏窗口拉到前面 |
| N8 | 开关放在专注条上 | 灰盒没有设置面板 | 正式界面按 04 放进设置 |

## 3. 验证

- `npm test` 全过（新加 13 条：25/5 两条各在 25、30 分钟；自动接下一轮；加 5 分钟报 30；暂停顺延；自己点结束和跳过休息不发；正向计时不发；没开、被拒、未决定、不支持都不发；一次推进碰到好几个终点只发一条；得了份和样式也一个字不提；副窗口不发；主窗口换人不重发）。`npm run typecheck`、`npm run build` 通过。
- 无界面 Chrome（`node tools/notify-smoke.mjs`，dev server 在 5199 端口；跑了三次，第一次因为下面这条发现等休息等得不够久超时了，加长等待以后两次都通过）：默认关、没问过权限 → 勾上问了一次，无界面里没人点允许，权限变成拒绝，那一句显示「浏览器没有允许通知，只在计时区显示」，之后 3 秒没有再问 → 用调试协议 `Browser.grantPermissions` 授权，那一句变成「结束时发一条系统通知」→ 开第二个窗口，是副窗口，勾选框也是勾着的 → 主窗口点继续，1 分钟专注到点：主窗口发了一条「1 分钟专注结束 / 接下来休息 1 分钟」，副窗口 0 条，小结那一行照常出现 → 在副窗口把开关关掉，休息走完主窗口也没再发；两个页面都没有报错。
- **发现**：第二个窗口打开以后主窗口转到后台，休息倒计时在剩 11 秒左右停住，有计时的两次分别停了约 45、15 秒，然后一次补上（心跳判为「在运行」，时间没丢）。也就是说主窗口在后台时，定时器被浏览器压住，**通知可能晚到几十秒到一分钟**。计时本身不受影响（按单调钟补），只是「到点」被发现得晚。浏览器里没有好办法：定时器都会被压，Service Worker 定时通知还没普遍可用。桌面壳里用原生通知可以按时发。

## 4. 小结那一层现在的样子（04 第 19.2、20.3 节）

灰盒里有：专注条上面一行 `summaryRow`，内容是 `present()` 的 `focus.summaryText`，来自内核 `focus.lastSummary`，在一轮结束（到点或你点结束）时生成：「这一轮 25 分钟 · 得 1 份 · 新样式：琥珀灯光」，没得份就只有时长。

符合的：不弹窗、不出声、不用点、不领取；内容按这一轮真实结算的份和样式汇总，不从时长推断；跟系统通知是两层，通知里没有这些。

对不上的，这次都没改（按约定小结不重做），等定了再动：

1. **自动接下一轮时，上一轮的小结一直留到下一轮专注里**（违背「专注进行中不提醒份数、冷却和解锁」）。用 25/5 加自动接下一轮跑 40 分钟，第二轮专注进行到 15:00 时那一行还写着「这一轮 25 分钟 · 得 1 份 · 新样式：琥珀灯光」；不休息（25/0）加自动接下一轮也一样。原因在内核：`focus.ts` 的 `startFocus`、`startNextRound` 会清 `lastSummary`，自动开始下一轮走的 `beginRound` 不清。改法：`beginRound` 里清一下（内核一行，另一个窗口在改内核，这次没动）；或者界面在专注条是「专注中」「正计时」时不显示这一行。建议改内核。
2. **不会自己收起**。04 说开始下一轮、你有操作或短暂停留后自然收起；现在只有开始下一轮会清，休息中、「准备好了就开始」里一直挂着，关掉再开也还在（`lastSummary` 进了存档）。建议界面层自己管显示多久（比如一两分钟后淡出，或你点了别的就收），不动内核。
3. 开始就点结束，会出一行「这一轮 0 分钟」。小事，可以 0 分钟不显示。
4. 小窗（320×180、480×270）只画场景，没有这一行。灰盒没有真正的小窗，留给正式界面。
5. 顺带一个要你定的：顶栏的九个点在专注进行中得份时会当场亮一个（04 第 4.2 节「当天获得几份就亮几个小点」），这和第 19.2 节「专注进行中不提醒份数」有一点张力。要不要让点也等这一轮结束再亮？

## 5. 要用户在 Safari 和 macOS 真机上确认的

1. **Safari 的询问框**：勾上开关时 Safari 弹不弹询问（Safari 只认点击当下发起的询问，现在是在勾选的那一下发的）；选了以后在「Safari 设置 → 网站 → 通知」里记没记住；拒绝以后再勾，确认不会再弹。
2. **macOS 的通知权限**：「系统设置 → 通知」里 Chrome、Safari 要允许通知，否则浏览器说允许了、系统也不显示，应用这边看不出来。勿扰和专注模式下会被系统收起，这是对的。
3. **后台和最小化**：主窗口最小化或被别的窗口盖住、切到别的桌面时，通知能不能出来、晚多少（无界面 Chrome 里晚了 15–45 秒）。主窗口在后台超过 5 分钟（Chrome 会把定时器压到一分钟一次）时再看一次。
4. **样子和声音**：标题、正文在通知中心里看起来对不对；系统默认提示音会不会响、要不要改成静音（04 的柔和提示音是另一回事）。
5. **两个浏览器同时开**：Chrome 和 Safari 各存各的，各有一个主窗口，会各发一条。这是浏览器里避不开的，桌面版只有一份。
6. **点通知**：现在不处理点击；看 Safari、Chrome 点了以后会不会把浏览器拉到前面，要不要这样。
