> Claude 2026-11-16。06 第 12 节的 1–4 条（合盖休眠、后台超过 5 分钟、连开 2–4 小时、Safari）要在真机上跑。灰盒现在会自己记日志，用户照常开着用，事后导出来，`tools/probe-check.ts` 逐项给「通过 / 可疑 / 没测到」。记什么、怎么判见 06 第 12.1 节。

## 1. 给用户的操作步骤

准备：终端里 `cd game && npm run dev`，Chrome 打开 <http://localhost:5173/>。先开 <http://localhost:5173/log.html> 点一次「清空日志」，让这一轮从干净的开始（存档不受影响）。

1. **合盖休眠**：点「开始专注」，过一两分钟合上盖子，等 5 分钟以上再打开，看一眼专注条。再做一次「休眠 1–2 分钟」的短的。
2. **后台超过 5 分钟**：开着专注，把灰盒那个标签页切到别的标签或把窗口最小化，干别的 10 分钟以上再切回来。中间不要合盖。
3. **连开 2–4 小时**：开着灰盒做平时的事，专注开开停停都行，中间别关这个标签页、别删档，也别点调试面板里的快进、模拟休眠按钮（点了工具会提示，那一段的数不算）。
4. **两个窗口**：再开一个标签页打开同一个地址（它会显示「副窗口」），过一会儿关掉原来那个，看新的那个接手。
5. **Safari**：在 Safari 里把 1、2、4 各做一遍（日志是每个浏览器各记各的）。
6. **导出**：每个浏览器里各打开一次 `/log.html`，点「导出 JSON」。页面上已经能看到判断；把文件交给我，或者自己跑 `node tools/probe-check.ts ~/Downloads/bts-probe-….json`。

顺序无所谓，可以分几天做；不清空的话日志会一直攒着（最多两万条）。

## 2. 无界面 Chrome 里跑过的

`node tools/probe-smoke.mjs`（真实时间，没有用 `--virtual-time-budget`）：开灰盒、开始专注 → 切到别的标签页 20 秒再切回来 → 用调试协议把页面冻结 130 秒 → 开第二个窗口 → 关掉第一个 → 第二个接手、继续专注 → 用调试器把它的脚本停 125 秒 → 在 `/log.html` 导出 → `probe-check` 读。

导出 49 条、4 个页面会话，`probe-check` 的判断：

- 日志本身和全程：**通过**。存档写 18 次、读 1 次，都没失败；倍率不变的那些跳，世界应走 4.8 个游戏分钟、走了 4（差的是不满一分钟的零头）；确认运行 48.1 秒，专注记了 48.1 秒。
- 第 1 项：**通过**。冻结 130 秒、脚本停 125 秒都判为「确认不了的断档」，在走的专注停在已暂停，留下了待选的时长；世界和专注在那一跳都没动。
- 后台 20 秒那一段：确认运行 21.015 秒，墙上钟 21.017 秒，专注照记。无界面 Chrome 在 20 秒里没有节流（最长间隔 1.08 秒）。
- 多窗口：**通过**。第二个窗口当副窗口，主窗口关掉后接手，离最后一次收到广播 1.0 秒；没有出现两个主窗口同时推进。

## 3. 跑出来的发现

1. **无界面 Chrome 把冻结的页面解冻时会重新载入它。** 解冻那一刻的 `pagehide` 里补了一次心跳，判为「确认不了的断档」并存了档；重新载入时按「退出过」读档，`exit` 盖过了 `gap`，「算进去 / 不算」的选择就没了，专注停在「电脑睡了一会儿」。这符合现在的规则（02 第 3.4 节：重开不给选择），不是 bug。真机上 Chrome 冻结或丢弃标签页后回来，多半也走这一条；日志里会看到 `open.nav = reload` 或 `discarded = true`，第 1 项会列出这次重开。
2. **页面被杀时还没写进 IndexedDB 的条目会丢**（第一次冒烟就丢了解冻那一跳）。现在每条同步抄在 `localStorage` 里，写进去才删；下次打开灰盒或导出页时补进去，重复的按会话 id 加序号去重。
3. **记录端的监听要排在运行时之后**：运行时在 `visibilitychange`、`pagehide` 时会补一次心跳，记录端要等它跑完才收「后台那一段」，否则回到前台那一跳（后台里最长的那一跳）会漏掉。当上主窗口时再注册一组收尾的监听解决了。

## 4. 判断的口径（以后看真机结果时要知道的）

- 第 1 项把所有「休眠 / 确认不了」都列出来，不知道哪一次是合盖；用户合盖的时刻对着看就行。冒烟里的冻结、脚本停住也会出现在这里。
- 第 2 项只看主窗口、5 分钟以上、中间没有休眠的后台。后台出现「确认不了的断档」判可疑：说明 Chrome 把定时器压到了 2 分钟以上一次，专注会在后台被停下，这时要调 `heartbeat.trustGapMs` 或驱动（06 第 13 节第 2 条）。
- 第 3 项的阈值（每小时漂 2 秒、确认运行占 99%、存档 150 万字符、堆内存涨一半且超过 30 MB）是「看着不对劲」的线，在 `src/app/probe/analyze.ts` 的 `LIMITS`，不是游戏规则。Safari 不给堆内存，要在活动监视器里看。
- 用过调试面板的快进、模拟休眠会被标出来，那一段的数不算真机表现。
