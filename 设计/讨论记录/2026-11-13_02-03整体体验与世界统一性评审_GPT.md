## 0. 评审摘要

**总体结论：方向成立，不需要再次整体重写 02、03。** 当前三条成长线已清晰区分：

1. **现实专注**：有独立价值的可靠电脑专注工具；自动累计份数、玻璃罐与真实手记；不驱动游戏中的必需柴粮或施工。
2. **木屋生活**：人物按游戏世界的时间自主采集、取暖、吃饭、休息、读书和分阶段修缮；安全而不机械。
3. **自愿探索**：玩家在外面主动控制；归家带来食材、特殊材料、物件、景色与故事，不是维持基础生活的义务。

**尚可增强的关键不在于「增加新系统」，而在于统一三条线的情绪与感知：** 现实工作一段时间后看向木屋，能看出那里真的发生过生活；出去一趟回来，家中留下不同的日常；修缮完成许多年以后，角色仍像一个人一样生活。

| 维度 | 现状 | 评审判断 |
|---|---|---|
| 现实专注与奖励 | 02 §2，03 §4；45 分钟冷却、10 分钟有效专注、午夜仅重置每日份、24 件样式 | 机制清晰；未来 UI 只需低打扰执行 |
| 角色自主行为 | 02 §6 的八级优先与项目工时限制 | 能维持生活；还需「习惯、动作连续性、闲暇配比」的表现约束 |
| 天气与世界观 | 02 §3–4，03 §1、§10、§13 | 气象站很有辨识度；各子系统的观测—行动—记录可更紧密 |
| 回访与长线成长 | 02 §7、§11，03 §3–4、§13 | 已有材料、阶段和事件；缺少一眼可读的自然回访体验标准 |

## 1. 游戏统一定位【沿用已确认，建议用于 04–06 的共同设计句】

> **现实中你在电脑前做自己的事；风雪气象站里，另一个人也认真过日子。你们不互相雇佣，偶尔彼此留下痕迹。你有空时，可以走出去发现更远的世界，再把它带回这间小屋。**

这不是「番茄钟奖励生存资源」，也不应做成「背景里自动运转的高效率工厂」或「桌面角落里的重度战斗游戏」。

判断每个新需求时问三句：

- **是否让现实专注更顺手、更少打断？**
- **是否使木屋中的人更像在生活，而非在执行玩家任务？**
- **是否让探险的发现改变家与记忆，而非只增加库存数字？**

若答案都是否，不应为增加内容量而强加。

## 2. P0：角色生活连续性——从任务表走向有习惯的人【建议，待讨论】

**已存在**：02 §6 的需要优先级、至少一段持续的动作、现实任务类别轻推；项目每日工时上限；03 有读书、观测、做饭、写日志、休息等内容。

**体验缺口**：如果实现仅按八级优先依次选下一项，前期「修缮→修缮→修缮」可能过密；休闲全在队尾，角色像劳工而不是伙伴。数值上保证了「项目不是工时配额」，并不自动保证画面里能看见闲暇。

建议最小增强（不加入好感度、复杂情绪条、随机 AI 对话）：

1. **稳定习惯**：例如清晨看气象仪器，夜里写简短观测日志；同样的天气下有重复而熟悉的动作。
2. **活动连续性**：正在读的同一本书、暂放的木工零件、上一阶段未完的整理，在适当时机被继续；不要每天随机重新选一件、没有因果。
3. **非产出时间**：基本生活已满足且没紧急补给时，读书、喝茶、看雪、发呆应在正常世界日自然出现；「项目最多 3/5 工时」只是**上限**，不是默认做满。
4. **设施带来的习惯变化**：修好椅子、唱片机、书桌、窗帘或水管以后，角色偶尔真实使用；不仅是面板新增一个图标。
5. **轻度现实同步**：只在已经允许的闲暇选择上影响倾向，绝不覆盖生存优先级，不模仿用户每一次操作。

**可验证的体验场景**：开局连续观察几个世界日，不操作、不给份、也不探索。观察者应能看到基本生活正常运转，且在没有紧急需求的日子至少有一些自然闲暇；同一本未读完的书或未完成的阶段能留下明确的延续。

**归属**：02 §6 的已确认原则不必改；04 定「能看到什么」，05 定自然动作衔接与停留，06 用轻量状态记忆使其不随机跳转。若将来需要修改行为权重或新增数值规则，再请用户确认。

## 3. P0：回访反馈——不增加日报弹窗，也能看出生活发生过【建议，待讨论】

**已存在**：02 §7 真实施工阶段、03 §3 可见物件与柴堆、03 §4 玻璃罐、02 §11 真实手记与年册。

**体验缺口**：这些系统可能在玩家认真工作时悄悄发生，用户回来时既没看到动作，也不一定愿意逐页翻日志。关键不是向玩家汇报一大堆数据，而是**让已发生的事情留下可读的环境证据**。

建议把回访分为三个层次：

| 回访耗时 | 玩家自然得到的信息 | 允许的呈现 |
|---|---|---|
| 抬头 2–3 秒 | 他现在在做什么、窗外天气、屋内大致安稳 | 角色动作、炉火、天气、柴堆、桌面状态 |
| 停留约十几秒 | 今天有什么小变化 | 已完成一餐、修缮阶段、新摆件、正在阅读的书或近期收获 |
| 主动打开手记 | 具体发生过什么 | 真实世界日事件、施工阶段、季节记录；现实任务只在现实栏 |

**硬约束【沿用已确认】**：

- 不弹出「你错过了 N 个事件」类打断提醒、不抢现实工作焦点。
- 应用退出、电脑休眠、氛围态或户外临时专注中，世界冻结；**不能捏造离线发生的活动**。
- 游戏界面只通过真实世界状态或实际事件呈现，不要随机伪造「已修好」「收了东西」。
- 对于环境本来不能留长久痕迹的事件（例如吃过一餐），可以在当前合理时段留下碗筷、桌面状态或在手记追溯，不必无条件持续到下一次打开。

**建议的验收演练**：持续正常陪伴 2–4 小时现实时间后回访，能看到时段变化以及至少一件实际完成的小生活事件；不强求每次都完成修缮。这个体验目标已经写在 01 §7，本稿仅把它具体化为呈现标准。

**归属**：04「完整窗/小窗、低打扰回访」、05「可见痕迹的镜头表达」、06「真实事件与当前场景状态一致」。

## 4. P0：把「气象站」做成统一叙事母题【建议，待讨论】

**已存在**：03 的泉屋、防风林、仪器角、前任日志、天气年性格；02 的天气前兆、不同天气劳动和出门判断；后期有长冬谜团。

无需增加「气象技能树」或每天强制填写观测任务。只需形成更清楚的一条因果链：

**观测天气 → 影响自主生活与自愿探索 → 在真实日志留下观察 → 多个世界年形成自己的站史。**

建议将下列内容联合检查：

| 连接 | 已有素材 | 建议表达 |
|---|---|---|
| 气象与作息 | 清晨仪器角、风雪前兆 | 角色自然看一次仪器，准备今天的劳动 |
| 气象与资源 | 天气限制院子劳动、秋备冬 | 好天气加工存粮，风雪天读书及安全近处补给 |
| 气象与探索 | 出门前观察、手册、预报 | 玩家愿意看天再选择路线；不看也不罚任务 |
| 气象与叙事 | 前任批注、旧观测资料 | 线索在正常生活与可选发现中渐渐出现，不强制追查 |
| 气象与年册 | 年份性格、初雪、暴风雪 | 年册是发生过的天气和生活之记录，不凭模板编故事 |

**建议**：完整版本可以把「每日观测」作为可见的角色习惯，原型先用一段短动画、一个仪器反馈和一条真实日志测试。未来天气主线增强，也不该改变玩家已确认的季节长度或默认安全生活边界。

**归属**：04 仪器交互／信息层次，05 声画前兆、仪器细节，06 天气事实源与记录事件关联；03 的气象站场景资产可作为统一参考。

## 5. P1：每次探索都应有「带回家后的生活变化」【建议，待讨论】

**已存在**：松林、溪谷、冰湖三张地图；独一份的书、唱片、布料、零件、胶卷；拓展修缮、道具、藏品。02 已确认「野外普通柴粮效率不高于家门口」，重点不应是刷物资。

建议给近处区域各安排一个「一看就记得住」的非生产体验：

- **松林**：落雪、静音、动物踪迹、林间旧工棚；发现书本或特殊木材后，家里出现可执行的读书/修缮行为。
- **溪谷**：流水、雾、旧桥与泵房；带回玻璃、零件或唱片，日后看见修暖棚、听见不同声音。
- **冰湖**：旷阔冰面、光影与观测小屋；带回旧胶卷或档案，可能成为可收藏的照片和日志线索。

不是每处发现都必须开一条任务链，也不是每次外出都要保证获得新奖励。应有宁静、观察和空手而归的空间。

建议把回家反馈分成三类：**功能变化**（某个真实项目终于有材料）、**生活变化**（多一道菜、一本书、一首唱片）、**记忆变化**（照片、风景、世界手记）。这比背包多一个计数更能体现探索价值。

**边界【沿用已确认】**：探索仍自愿，基础生活和基础修缮不依赖探索；户外风险温和可恢复；不加技能树、Boss、永久死亡或效率碾压。

**归属**：03 §5–7 现有物件表不必扩增数量；04 设计返家/物件详情的低打扰回音，05 设计三个区域的视听差异，06 建立发现→物件→真实项目→场景变化→手记的事件关系。

## 6. P1：统一「拥有样式—能否应用—角色亲手更换」【建议，待讨论】

**已确认**：24 件、累计 556 份解锁；前 8 件内容已定；样式不增加生存数值；现实累计小时单独记个人纪念；实物样式由角色择机更换，灯光与声景设定立即生效。基础灯光、风雪、炉火与生活声永远可用。

**体验风险**：后期窗帘、灯罩等样式与设施修缮存在依赖。专注用户可能很早就拥有样式，却长时间不能在真实世界应用；这不意味着规则错误，但必须**让玩家明白自己已获得什么**。

建议 04 统一表示三种体验状态：

1. **已拥有、可直接使用**：声景、色温或已存在物件的外观。
2. **已拥有、待设施具备条件**：窗帘等实体，清楚提示依赖哪个实际修缮；不会失去拥有权。
3. **已选择、等待角色自然更换**：真实世界里角色在安全且空闲时完成；氛围态可以立即预览，但不伪造已经完成的物理修缮。

**不得**为了让样式立即可用而暗中把没修好的设施修好；也不应该让未完成探索的纯专注用户长期感到「奖励丢失」。若 04 原型发现这种阻碍显著，优先调整同类样式的展示或不影响机制的替代显示，再决定是否需要提议修改 03 第 9–24 件的内容（须用户确认）。

## 7. P1：修缮结束后的日子不是「等下一张内容表」【建议，待讨论】

现有十项修缮、真实种植、近处探索、24 件有限样式、四季和世界年册，已经有足够长的内容骨架。需要设计的是**成长重心如何自然从「恢复设施」转向「享受生活」**。

建议把内容体验理解为四段自然变化，而不是新成就等级：

| 生活段落 | 玩家主要感受到什么 | 新增系统？ |
|---|---|---|
| 初到站里 | 认识动作、炉火与人物习惯；旧站尚有待修处 | 不需要 |
| 慢慢安顿 | 基础修缮、天气、菜地和真实生活越来越顺 | 不需要 |
| 熟悉附近 | 自愿探索，带回新书/唱片/材料，生活方式更丰富 | 不需要 |
| 多年以后 | 常见活动有了个人习惯，季节和记录持续构成回访理由 | 不需要 |

特别要防止：所有项目做完之后，角色失去动作目标，画面成为随机循环；或者反过来为了「长期目标」硬加永远修不完的设施。

**验收**：在测试存档中直接设为「十项修缮已完成、24 件已获得、近处探索已走过」，模拟多个世界日，角色仍能正常饮食、观察、阅读、闲暇、使用已修好的设施；季节有实际变化，年册只记录真实事件。无需刷新项目、无需玩家每日报到。

## 8. P1：统一感官与界面语言，避免变成三个独立小游戏【建议，待讨论】

**环境基调【沿用已确认】**：屋内暖色、户外寒冷，克制的 16-bit 像素美术；动作与环境优于多话；声音以风雪、炉火、生活声为核心，音乐默认关闭。

跨状态体验建议：

| 世界状态 | 主要信息与操作 | 视觉/声音 |
|---|---|---|
| 正常陪伴 | 木屋和角色，必要时点设施看状态 | 真实天气、真实生活、极低 UI 干扰 |
| 独立氛围态 | 自选天气/季节/时间，自选声音，不推进世界 | 明确「这是预览/氛围，不是当前真实日」，不写事件日志 |
| 户外直控 | 体温、体力、生命、背包与路线 | 视线聚焦探索，UI 强度可比木屋高，但保持同一套像素语言 |
| 户外临时专注 | 木屋镜头（可空屋），角色与世界冻结 | 计时与声音正常；回到野外仍在原地 |

**建议原则**：「世界状态决定镜头与信息密度，现实专注决定低打扰程度」，而不是另造第二套奖励和成长体系。

04 重写时特别要核对：**跨午夜的现实份数显示、休眠后暂停、异常断档自选计时、氛围预览、户外临时专注返回、锁屏与后台**；这些已经在 02 定义，不应在 UI 稿中重新改规则。

## 9. P2：现阶段不建议扩张的内容

- 不新增永久好感度/情绪条、关系升级或大模型实时对话。
- 不新增「每天观测天气」「每日清任务」「回来领取奖励」的强制日常。
- 不为了长期陪伴增加无限家具、无限装修、技能树与永久重复维护。
- 不把三张初期探索区域转成以高效率刷柴粮为主的地图。
- 不让霜兽、远行与长冬真相抢走首个 Web Demo 的注意力。
- 不在 04/05 阶段重新改动已确认的 45 分钟得份、00:00 换日、资源真实性和季节结构。
- 这轮暂不继续审计柴的重量换算、个别台词或无限风雪假设；另有需要时单独回到数值/世界观验证。

| 06 技术与版本 | 单一世界事件事实源、持久化、可回放的场景/日志关系、Web 到 Mac 的一致性、性能/省电、可验证原型 | 将设计期脚本的统计直接宣称为实机体验 |

**协作建议**：02/03 主体作为已确认版本保留；新增体验内容暂以本评审为「提议」。如后续选定某项导致真正的行为规则变化，先由用户确认，再更新正文与 00。已经确认的 O1–O4、R1–R11 不应因这轮体验讨论自动撤销。

## 11. 验证场景与建议的验收方式

建议在 04 UI 原型、05 视听草案、06 可运行 Demo 使用以下**体验验收**，与现有的资源脚本验收互补：

| 测试场景 | 期待看到什么 | 什么算偏离 |
|---|---|---|
| 电脑连续专注 2–4 小时 | 实用计时不中断；木屋自然经过时段，发生真实小事，回访一眼看懂 | 被游戏要求点击领奖、照顾生存或打开日报 |
| 一周只用专注，不出门 | 基础生活继续，角色会修基础设施，已有样式实际可见 | 基本生活依赖份数，专注奖励频繁提示不可用 |
| 一周只看木屋，不开计时 | 人物自主过日子、种植修缮与天气照常变化 | 没有番茄钟就无法前进 |
| 连续多个世界日正常陪伴 | 人物有可辨习惯、同一活动有连续性，不只是循环工人 | 总在最高优先级项目上机械工作 |
| 松林/溪谷/冰湖各往返一次 | 三地有不同记忆点，带回的真实物件会改变后续家中生活或日志 | 三张地图只是在刷不同颜色的原料 |
| 独立氛围态或户外临时专注 | 可专注、得份，世界冻结，回来正确恢复位置和状态 | 伪造时间/施工/资源/日志 |
| 全部修缮已完成的老存档 | 依然有天气、生活习惯、自然闲暇与真实年册 | 没工程后人物不再值得观看 |

建议避免提前在设计文档发明大量新百分比；先用小型可运行 Demo、回访录屏和真实用户工作时段观察确认「这间屋子确实值得放在桌面旁」。

## 12. 处理状态与建议的下一步

**本评审提出的是待讨论的体验增强，不改变 02/03 v3.0 的已确认机制**。我建议按以下顺序继续：

1. **04：** 先完成回访三层反馈、四种状态、小窗、专注恢复与展示位交互的统一 UI 方案。
2. **05：** 复用已有资产，把「人物习惯/场景痕迹/气象仪器/归家变化」做成最小动画与音效清单，先验证几种自然生活事件是否可辨。
3. **06：** 给真实事件记录、项目、物件、天气、角色行为建立能够在 Web/Mac 共同复用的状态与事件接口，并做可长跑的场景验证。
4. **讨论或用户确认：** 如果上述原型显露 02/03 需要实质性调整的机制，逐项讨论再修改，不在未授权情况下改定稿内容。

**一句话结论**：不要再为《风雪之外》堆加系统；要让一个真实运行的气象站、一位有习惯的居住者、一段认真工作后的回访，以及一次自愿探索的归家，共同表现成同一个世界。
