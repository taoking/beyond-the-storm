# 05｜美术与音频

> **状态：v0.2 分层制作与窗下书桌方向补充（2026-11-13），仍是视觉试片阶段，非最终美术定稿。** 以 01 v2.7、02 v3.0＋六条确认补充、03 v3.0、04 v1.3 为依据。GPT 负责界面图片/分层视觉资产，Claude 负责游戏工程；视觉与交互设计双方共同评审。
>
> **目标**：将 16-bit 像素画、木屋全景、雪窗/炉边两个小窗镜头、阅读/喝茶/观测天气三个角色动作做成一套可复用的场景系统，而不是三张互不相干的插图。视觉演示不改变真实世界时间、资源、修缮、奖励与角色位置。

## 1. 视觉方向

**一句话**：屋里是温暖、熟悉的秩序，窗外是缓慢辽阔的寒冷；角色不为玩家表演，但抬眼就知道他正在生活。

画面首先要看见 **窗外风雪、壁炉暖光、人物活动**。现实专注和统计只能安静地附着在边缘，不成为第一视觉中心。

- 基础风格：现代手工 16-bit 像素场景，2D 横向剖面/轻正面视角，冷蓝雪景与暖橙炉光对比。
- 不用照片化滤镜、模糊描边、过量 bloom、漂浮全屏雪粒、写实 UI 质感替代像素细节。
- 场景统一空间坐标：镜头是从同一间木屋裁切，不为不同镜头重新安排家具位置。
- 暴风雪只在窗外和户外出现；屋内烟汽、炉火、茶杯可以轻微活动，支持减少动态效果。
- 角色不能机械地连续工作；休息、看雪、读书和发呆都有合法出现的空间。

## 2. 场景基准和三镜头【制作初值】

建议以 **480 × 270 逻辑像素、16:9 比例**做首轮结构原型，使用整数倍 nearest-neighbor 缩放；最终逻辑分辨率可在 384×216、480×270、512×288 中比较后确认，**当前不是用户确认的硬性分辨率**。

| 区域 / X 参考范围 | 关键场景 | 可视化状态 |
|---|---|---|
| 左侧 0–55 | 门、堆柴、壁板 | 人物出入、柴架状态 |
| 中左 56–220 | **大雪窗**、远山、近松、球果罐 | 真实天气、窗景、微痕迹 |
| 中央 220–325 | 书桌/书架、人物 | 阅读、写记录、泡茶、收拾 |
| 右侧 325–480 | **壁炉**、壶、坐席、仪器角 | 火焰五态、温暖生活、观测 |
| 底部 208–270 | 地板与家具脚 | 保留走动空间，不让 UI 遮住场景 |

### 2.1 三个镜头

| 镜头 | 主要内容 | 用途 |
|---|---|---|
| WIDE 全景 | 雪窗、人物、炉火三锚点同时可见 | **完整窗口默认**，侧栏收起 |
| WINDOW 雪窗 | 冷雪、树影、窗框、玻璃罐、暖光边缘 | **紧凑小窗默认**；允许人物出镜 |
| HEARTH 炉边 | 火苗、壶汽、椅子、毛毯和木墙纹理 | **紧凑小窗可切**；允许人物不在取景内 |

**U2 已确认**：人物出镜头时不自动追随。小窗只用真实状态短句说明他在哪里，不因此增加摄像机运动。完整窗和小窗分别记镜头偏好。

## 3. 像素资产规范【待原型验证】

- 以 1–2 逻辑像素描轮廓，以 2–4 像素表现家具主要结构；同一材质主色、亮面、阴影及深影通常用 3–5 个色阶。
- 光照用一层层像素对齐的色块，不用半径模糊；炉火可以轻微跳动，但不会像庆祝特效一样突然爆亮。
- 角色比例建议头身约 1:3 到 1:3.5；红帽/围巾及深色外套保持易辨，不强依赖细小面部表情。
- 墙与木板可用少量可复用纹理，窗外松树/雪花不应成为密集噪声；不要把文字写在背景像素画上再叠加第二层 UI。
- 场景渲染应关闭纹理平滑；文本采用可读性好的系统字体，像素字体只适合短标题或世界标签。

## 4. 阅读、喝茶、气象观测三个核心生活动作

**这三种动作是角色自主生活的视觉表现，不是玩家即时命令。** 演示原型中可以手动切换动作以检查可读性，但正式游戏应由 02 的角色行为状态驱动。

| 动作 | 关键帧与姿态 | 真实关联 |
|---|---|---|
| READ 阅读 | 坐在桌边、书摊开、头向下、偶尔翻页 | 真实读书/项目状态，阅读对象可延续 |
| TEA 喝茶 | 拿起杯子、抬到嘴边、放回、轻微蒸汽 | 自主休息/泡茶与已有热源 |
| OBSERVE 观测天气 | 起身面向窗边/仪器、读数、做笔记 | 实际天气和观测日志 |

首轮可验证约 6–8 fps、各动作 2–5 个核心帧，并保留较长停顿；不为了“动态”让人物每几秒随机瞬移。正式版在桌边与仪器角之间需补少量过渡帧。

## 5. 环境反馈与回访

| 画面物件 | 触发 | 视觉边界 |
|---|---|---|
| 球果罐 | 份数立即入现实手记，人物空闲时整理 | 未整理不能展示为已经放好；不进入柴粮库存 |
| 茶杯/翻开的书 | 真实动作之后短暂留下痕迹 | 状态有自然生命周期，不能永远保持“刚喝完” |
| 炉火 | 炉膛真实燃料、添柴行为 | 熄灭、余烬、小、中、旺五态不混同 |
| 气象仪器 | 角色确实进行观测 | 不自动生成新的观测任务奖励 |
| 修缮外观 | 真实项目阶段和施工结束 | 不能由专注奖励直接修好 |
| 天气 | 02 真实天气或独立氛围演出 | 窗外裁切雪粒，预览不生成世界事件 |

回访以**看见人、火、天气 → 发现茶杯、书本、工程痕迹 → 自愿翻真实手记**为顺序，不发总结弹窗。

## 6. 音频：温柔而不强迫参与

| 层 | 最小素材 | 使用方式 |
|---|---|---|
| 风雪 | 远风、小雪、暴雪 | 与真实天气或氛围预览匹配，音量独立控制 |
| 炉火 | 添柴、低火、正常火、余烬 | 与炉火真实状态一致 |
| 室内生活 | 翻书、杯子、木椅、脚步、铅笔/仪器 | 在对应真实动作发生时播放，不随机加“完成音” |
| 户外自然 | 松林风、溪流、偶尔鸟鸣 | 随环境与季节变化 |
| 唱片/电台 | 后续收藏/设施对应音乐 | 默认关闭，未修设施不假装真实可用 |

基础风雪、炉火和生活声始终可调节；音乐默认关闭。不要为每一份或每个普通项目进度增加强制提示音。

## 8. 验收、限制与后续

- **构图**：全景能同时识别雪窗、人物和炉火；缩成约 400px 小窗后仍能辨认雪窗/炉边且 UI 不遮挡关键景物。
- **动作**：三个姿态在全景下明显不同，人物离开镜头时不自动追踪；状态描述可信。
- **时序**：切镜头、切小窗不创建第二世界，不额外推进时间；独立氛围与户外临时专注严格冻结世界。
- **动效**：雪粒只在窗外/户外，火苗变化低频且可关闭；环境音默认不抢现实工作的注意力。
- **真实性**：角色行为、手记、罐和修缮只引用同一事实事件；视觉原型数值仅供演示。

**当前尚未完成**：正式像素母图与精灵图集、实浏览器视效验收、Web/Mac 性能及休眠验证。先做一份低分辨率、画面元素分层的可操作场景原型，再据此确定 05 的正式像素美术资产规格。

> **本文件为设计建议和制作规范，未标注已确认的数值、美术资产规格、人物帧数与配色均可在视觉试片后调整。**

## 9. v0.2：依据 Claude A1/A4/A5/A6 调整的可制作资产方案

**来源**：[Claude 04 设计意见](讨论记录/2026-11-13_04设计意见_Claude.md)；[04 v1.3 交互规格 §19](04_UI与交互.md)。这是一份**制作要求**，不是宣布当前 05 HTML 构图已经完成改造。

### 9.1 窗下书桌先于完整窗精修

母场景中的**雪窗位于书桌上方**，窗台球果罐与桌前人物同处一个小窗裁切空间。构图不要用「窗口上半幅特写」代替：至少能辨别窗外天气、罐的存在、人物阅读/写字的基本姿态。

- 候选空间关系：**上层**（雪窗＋远山＋窗框）／**中层**（窗台与球果罐）／**下层**（桌面＋坐姿人物）在同一局部 X 范围内。炉火在母场景右侧、书架可向两者之间收纳；正式坐标必须通过像素试片决定。
- **320×180** 和 **480×270** 分别作实际窗口截图，不只是放大后的看板图；检查人物轮廓、球果容器、计时和九点在桌面角落是否清楚。
- WINDOW 镜头可针对小窗使用**更低更宽的像素对齐裁切**；旧试片采用 `x=43, y=30, w=195, h=111`，**目前无法同时完整容纳书桌人物，是待替换旧裁切，不要直接按它制作最终美术**。
- 不能因为用户希望小窗常见人，就让角色凭空瞬移、无限坐桌、或恢复已确认的不追人规则。以后借 06 灰盒记录实际可见时长。

### 9.2 分层制作清单与命名建议

| 资产组 | 建议层名 / 文件意图 | 可变触发 |
|---|---|---|
| 静态室内基础 | `cabin_base`、`beams`、`floor`、`static_furniture` | 不随换天气和份数改变 |
| 独立窗外层 | `window_sky`、`window_far_mountain`、`window_trees`、`window_weather` | 季节、天气、昼夜；窗框作为遮罩 |
| 光照层 | `fire_glow`、`lamp_light`、`daylight_tint` | 炉火强度、时段、色温样式 |
| 生活资源层 | `stove_state_0..4`、`woodpile_tier`、`food_rack`、`cup`、`book` | 真实炉火/库存/角色活动 |
| 施工层 | `repair_<id>_stage_<n>` | 真实工程阶段，不受份数驱动 |
| 球果罐 | `jar_container`、`jar_fill_tier` | 待整理份数→真实人物整理→改变填充层 |
| 展示位层 | `display_photo`、`display_window`、`display_desk`、`display_mantle`、`display_bedside`、`display_wall` | 03 六处确认位置及对应拥有/可用状态 |
| 角色服装层 | `actor_indoor`、`actor_outdoor`、`actor_accessory` | **室内毛衣便服，室外帽与围巾**；服装样式从已获得内容选取 |
| 动作与位置 | `actor_pose`、`actor_prop`、`actor_position` | 阅读、泡茶、气象观测、行走、备柴等状态 |
| 院外远景候选 | `yard_far`、`worker_silhouette`、`tracks` | **仅原型对比 A4，是否正式制作待灰盒可见率验证** |

**重要**：AI 生成的漂亮整张图不是上述透明资产集。设计阶段可先通过程序化像素试片验证像素密度、坐标和构图；随后分别产出可编辑、有透明度、边缘对齐且颜色稳定的图层，复核每个状态的遮挡关系。

### 9.3 少帧动画与程序换色的现实约束

- 人物设计时以**共同基础身体/姿势**、少量手持物与手臂层来构造阅读、茶杯、仪器观测；先做 2–4 关键帧并拉长静止停顿，之后再决定是否加细分动作。**不让不同 AI 输出的 4 帧分别生成不同头身比例。**
- 换色的毛毯、围巾、毛衣、帽子、窗帘等先限定低数量的稳定色板和遮罩；避免用复杂渐变背景做色键替换。已有 24 件样式内容以 03 正文为准，**不要擅自断言“八套”都属于同一布料或可一键纯换色**。
- 不靠透明像素直接推导所有命中区域；交互区域须为可调的几何遮罩，与不同镜头裁切和键盘焦点区域保持一致。
- 每张分层试片必须附注：逻辑像素尺寸、左上锚点、图层排序、透明边界、调色板、对应世界事实字段、候选预览还是可用资产；供 Claude 工程接入验证。

### 9.4 A4 院外可见率：先两张便宜的试片

同一全景先比较**A：院外远处小人影**与**B：空景＋脚印＋远处作业声＋短去向说明**。两方案都不能遮蔽雪窗、炉火和室内角色的主要阅读位置。实际采用哪一种，应等灰盒记录人物在屋内/院子/远处的时长和桌面小窗观看效果。

### 9.5 交付方式和当前尚未完成项

**目前已有**：05 v0.1 的低分辨率程序化场景、三镜头/三状态试片，以及场景状态映射 JSON；这些可继续作为研究资料，但需要按 v0.2 **更换雪窗裁切和人物室内服装设计**。

**本次新增的是规范，不是新图片或动画**。下一轮视觉工作按「窗下书桌的 320×180 / 480×270 实际尺寸试片 → 完整窗 1280×720 → 三个角色动作统一模型 → 分层透明资产」顺序推进。交 Claude 时以图层契约为准，不以旧演示 HTML 的固定书桌坐标作为最终世界布局。
