## 1. 目标画面的一句话

**窗外是一片真正冰冷的雪夜，木屋里一个人自然地生活；窗下桌前能看见他的背影，炉火在另一侧安静地燃烧。** 让木墙、书、灯、记录本和窗外的树有可辨识的像素材质，而不是由几何色块代表。

### 静态母图的构图与美术要求

- 固定 16:9 横向场景，**左侧 40%～50% 是大雪窗**，窗下书桌在窗的空间范围内；室内人物的轮廓与书/杯子在 480 小窗一眼可辨。
- 右侧以柴炉、火光、壶汽作为温暖中心；窗外松林是冷蓝、深蓝、高亮雪色层次；室内木板/织物/书本有不同的材质色阶。
- 中段观测站的书架、记录和已有仪器提供身份感；少量装饰需要对照 03 已有内容，不把不确定物件视为开局已拥有。
- 光不是一张橙色覆盖层：炉火点亮近处地板、人物边缘、桌脚和木墙；墙面仍有暗部；窗玻璃的冷光与室内暖光各有来源。
- 角色即使静止也像是在生活：看书/记录时姿态自然，不要永远同一帧；**真正的动作帧与位置仍要由真实世界状态驱动**。
- 母图中**不得绘制任何 UI 字、任务面板、血/饥/温度条、等级、每日打卡或系统通知**；不自动新增猫狗、家具系统和角色命令。

### 画面的一致性规则

1. 全景、雪窗、炉边来自**同一个木屋空间与美术母场景**，所有物件坐标和透视一致。可以为小窗单独制作高质量近景取样/高密度画法，但它必须与全景表现同一套布局，而不是角色换了位置。
2. 首个可运行资产版本必须有**真正的无人 clean plate**；不能把“人已经画在背景里”的概念图拿去假装角色会自行离开。
3. 炉火五态（熄灭／余烬／小火／正常／旺）是炉膛独立素材与光照状态；静态木屋不能永久画着旺火。
4. 窗外雪、天空、松林与窗框分层，**天气永远不能穿透窗框飘到屋里**。
5. 开局不会自动拥有所有样式与修缮。只把最初真实有的物件画进固定层，条件性物件必须按状态拆出。

## 3. 视觉质量验收：两条完全独立的线

### A. 美术品质（用户判断）

- 看 1280×720 的**纯木屋画面**，能否从材质、色彩、光影、人物姿态明显看出接近用户喜欢的效果图？
- 缩到 480×270：窗下人物手里的书是否可读，雪夜窗口是否足够大，炉火/桌灯不抢现实工作注意力？
- 缩到 320×180：即使不能看清书名，也能分辨人在写/读、窗外在下雪；无角色时画面仍然成立。
- 暖光亮处有层次，木屋暗处不糊成一块，雪景不是纯蓝色矩形；人物不会像贴纸漂浮在背景上。

### B. 工程可用（自动化验收）

- 背景、角色、窗外、炉火、光照是实际不同透明素材或可独立绘制层；不是一张效果图加假透明矩形。
- 隐藏人物时**没有衣服/手/背包残影**；隐藏炉火时不留旺火与橙色地板亮斑。
- 图层按合成顺序重组正确，sprite anchor、sourceRect、裁切和缩放一致，真正存在的状态才可见。
- 真实浏览器截图/灰盒回放的证据与导出的素材版本绑定，不宣称静态概念图已经通过自动化美术验收。

**A 不达标时，B 即使通过 100 个测试也不能叫“高保真美术完成”。**

## 4. v0.7 LOOKDEV 参考包的限制

本轮为视觉对齐生成的 v0.7 美术方向板及**从方向板中裁切**的无 UI 画面，包含全景与雪窗/炉边局部、调色参考，以及一个本地 HTML 三镜头预览器。

- 这些 PNG 是**单层概念参考**。由于源图里已经画了人物、窗外天气和火焰，裁切不能生成真正的 clean plate、独立角色或者火焰五态。
- 参考包在本次对话以 ZIP 附件提供，**未通过 GitHub 的 UTF-8 文本文件工具上传二进制图片**。用户与 Claude 同步时可以把 ZIP 放到自己的工作目录；GitHub 此处只有规格与制作合同，不能假称已提交了 PNG。
- 本地生成的参考预览器通过 **Chromium 12 组尺寸×镜头组合**的脚本式检查；测试的是静态目标画面取景，不是正式原型/06 状态绑定。Safari/macOS 多屏未测。
