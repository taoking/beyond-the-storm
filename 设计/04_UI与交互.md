# 04｜UI 与交互

> **状态：v1.5 户外按动作走对齐（2026-11-15），木屋与小窗仍为 v1.4 试片。** 依据 01 v2.7、02 v3.2、03 v3.2、05 高清插画规格。GPT 负责视觉与交互原型，Claude 负责游戏实现；尚未完成正式美术、Safari 和原生 Mac 窗口验收。
>
> **标签**：【已确认规则】来自 01–03；【已确认 UI 方向】U1–U6 用户已原则采纳推荐值；【交互建议】细部交互和布局仍可在原型后微调；【后期】首个 Web 原型不承诺。布局线框和演示 HTML 不决定 05 的最终像素稿、尺寸与逐帧动画。先验证 Web，之后正式适配 macOS。
>
> **04 的成功标准**：工作时不打扰；抬眼看得出另一个人正在生活；回访能发现真实变化；想干预时只表达轻微意向；出门时才进入游戏操作；世界冻结与正常陪伴绝不混淆。

## 0. 必须服从的交互原则

1. **现实优先【已确认规则】**：不抢键盘焦点，不弹出必须关闭的奖励窗，不以领取份数、做饭或储粮要求用户打断工作。任务可以不选择，专注可以只按一次开始。
2. **画面先于数字【已确认方向】**：炉火、人物动作、柴堆、天气、已修设施首先由画面说明。具体库存、项目材料等只在点击或手记中显示。
3. **角色有自己的生活【已确认规则】**：玩家只能查状态、排可选项目、选样式或提出小请求；不能指挥添柴、备粮、做饭或在屋内用 WASD 操作角色。
4. **世界事实和氛围演出分离【已确认规则】**：正常陪伴只展示真实天气与世界进度；自选季节/天气/时段进入独立氛围态，真实世界冻结；户外临时专注也冻结。演出不消耗资源、不修项目、不造日志。
5. **回访不等于日报【交互建议】**：回来看场景得到信息，不自动弹“刚刚发生了 N 件事”；想知道细节才翻手记。
6. **两条时间线清晰【已确认规则】**：现实日期、现实专注、当日九份与世界日、季节、天气、角色经历严格分开；00:00 仅重置现实当日份数。
7. **低压力一致性【已确认规则】**：屋内丰足／正常／俭都不出现逼玩家救援的弹窗；户外的体温/体力/生命信息只在主动探索时提高显著性。
8. **不为 UI 增设机制**：本稿不新增好感度、精力条、日常签到、额外商店、额外生存命令或必须按时处理的事项。

## 1. 信息架构：两个世界视图、四种世界状态、三种窗口形态

### 1.1 两个视图【已确认规则】

- **木屋视图**：正常陪伴的主画面；能看室内与院子、观察角色、查设施、开专注、翻手记。若人已出门，默认户外临时专注时看到的是**空木屋**，角色真实位置不变。
- **户外视图**：仅在主动出门之后直接操控；查看地图、背包、采集、避险和走回家。镜头变化不代表瞬移或自动返家。

### 1.2 四种世界状态与最明显的 UI 区别【规则来自 02】

| 状态 | 主画面/可做的事 | 世界推进 | 专注计时 | 界面提醒 |
|---|---|---|---|---|
| 正常陪伴 | 木屋真实日常、设施意向 | 正常推进 | 可以有效计时 | 顶部只显示真实世界天气 |
| 独立氛围态 | 自选季节/天气/时段，循环闲暇演出 | **冻结** | 可以有效计时并得份 | 常驻克制的「氛围预览 · 世界暂停」 |
| 户外直控 | 户外移动、采集、动物、背包 | **按动作花游戏分钟，站着不动不走** | 直控时不算有效专注 | 体温/体力/生命与路程明显可见 |
| 户外临时专注 | 默认空木屋，也可自选氛围画面 | **冻结，角色原地不动** | 可以有效计时并得份 | 「户外暂停 · 返回原地」入口清晰可见 |

【交互建议】状态指示符的作用是防止把氛围画面误认成真实世界，而不是做成警告徽章；在小窗里只保留短文字或一个可说明的符号。

### 1.3 三种窗口形态【方向已确认；实现与可用性由 06 验证】

| 形态 | 用途 | 内容强度 | 实施边界 |
|---|---|---|---|
| 完整窗口 | 回访、任务、手记、设施意向、户外直控 | 可展开功能侧栏 | Web 原型优先 |
| 紧凑小窗 | 桌面角落陪伴、实时看计时与木屋 | 画面＋很少控件，悬停时才出现操作 | Web 先做紧凑布局或独立浏览器窗口；**不承诺浏览器一定能系统级置顶或不抢焦点** |
| 菜单栏面板 | macOS 后续：只听声音、看计时，随时打开小窗 | 不持续绘制大画面 | 桌面版实现；不要硬搬 Web 平台能力 |

【交互建议】完整窗口和小窗共享同一份**世界状态、专注会话与奖励记录**，镜头偏好可以不同。打开第二个窗口不能让游戏世界计算两遍或产生两个独立计时器。

### 1.4 日常典型路径

- **开始工作**：打开或恢复 → 看到木屋和计时 → 一键继续上次计时预设／任务，或者只看木屋。
- **抬头回访**：先看到人物和天气 → 再看到炉火/家具/当前动作 → 可选开一眼状态卡或真实手记。
- **临时想看另一种雪景**：选择独立氛围态 → 明确知道世界冻结 → 自选演出，现实计时照走 → 点击「回到今天」恢复。
- **想出去走走**：先从木屋点门开行囊 → 准备补给和看天 → 人物真实出门 → 玩家控制 → 走回家入库。
- **人在野外突然要工作**：打开专注 → 原地冻结、镜头切空木屋 → 可以自选氛围 → 完成后仍停在临时专注态，主动点「回到野外」。

## 2. 默认完整窗口：木屋优先，专注工具随取随用【交互建议】

### 2.1 推荐的整体层级（不是最终像素布局）

    ┌────────────────────────────────────────────────────────────┐
    │ 世界第 12 天 · 冬 · 小雪   [真实陪伴]      份 ●●●○○○○○○     │
    │                                                            │
    │                 木屋／院子主场景                             │
    │     角色当前动作、炉火、窗景、设施进展、玻璃罐、仪器角         │
    │                                                            │
    │ [在读观测员手册]  [镜头] [氛围/回到今天] [声音]                │
    │ 现实专注 25:00  [开始/暂停] [任务]   [手记] [侧栏] [出门]       │
    └────────────────────────────────────────────────────────────┘

- **推荐初始**：画面优先、侧栏收起（沿用旧 U3a 的推荐方向），但完整窗口要有稳定、无需寻找的开始／暂停入口；用户可以主动展开任务与统计侧栏。
- **世界时间与现实计时分别标示**。顶部世界日/季节/天气只是游戏事实；底部专注数字只是现实时间。现实日期通常不必占用木屋场景。
- **静态画面比例高**：不强制让计时数字以大号居中显示，不用奖励进度条压过风雪与炉火。
- **窗口太窄**：底栏可折叠图标，优先保留计时＋开始/暂停、声音和返回入口；绝不让真实正在进行的专注因为布局切换自动停止。
- **鼠标不动时**：多数底栏功能淡出，计时和真实状态标志仍能辨认；悬停、键盘聚焦时恢复。高对比/减少动态设置可以禁止隐藏动画。

### 2.2 回访「一眼三层」【本轮评审核心建议】

| 观察程度 | 要让玩家知道 | 主实现，不新增奖励 |
|---|---|---|
| 2–3 秒扫一眼 | 他此刻在做什么，木屋是否安稳，今天专注还有多久／已经多久 | 当前真实动作、天气、炉火、计时 |
| 多停留十几秒 | 这里刚刚完成了什么可见的小变化 | 项目阶段、桌面书本、水壶、收获、摆件、窗台小球果 |
| 主动翻手记 | 世界日里真实发生过什么、现实专注具体记录 | 世界日志与现实日志各自独立、按事实入账 |

**严守事实**：仅显示**真正运行过的时间**里发生的事。即使用户关机三天再打开，不能生成这三天角色做了什么的“欢迎回来”摘要。场景痕迹也要有自然生命周期：刚吃过饭可以有碗，过很多游戏小时不会仍假装刚吃完。

【交互建议】不新增「过去几小时事件时间轴」常驻控件；在当前动作文字旁提供「看看今天」入口，打开的仍是已有世界手记当天条目，不额外生成一份日报。生活变化以场景为主，文字为辅。

### 2.3 丰俭与库存怎样可见

| 档位 | 场景语气【沿用 02/03】 | 点击查询 |
|---|---|---|
| 丰足 | 桌上多样的食物、较宽松的作息、温暖炉火 | 查看当日档位与柴粮实数 |
| 正常 | 简单温暖的吃饭、读书与劳动 | 查看当日档位与柴粮实数 |
| 俭 | 节约使用柴粮，毛毯、热水、低火但不凄惨 | 显示「俭 · 简单地过日子」，无求救按钮 |

- 生活档位由 02 **每天起床时判定一次，当天不频繁跳档**；UI 不自行按当下库存重新推导一个不同结果。
- 具体柴、粮数量只在点柴堆、地窖、库存页时出现；**不在主画面永久放生存进度条或红色危机提醒**。
- 毛毯是持续可用的样式展示位，**不要把它仅放在丰足状态出现**，以免和 03 第四件样式冲突。
- 暴风雪、资源少、施工缺料都可以自然显示状态，但不产生必须由玩家处理的紧急任务。

## 3. 木屋镜头与人物不在画面中【交互建议】

### 3.1 镜头候选

| 镜头 | 主要表现 | 默认 |
|---|---|---|
| 屋内＋院子的全景 | 空间关系、人物进出、炉火、雪窗、院子 | 推荐完整窗口默认 |
| 雪窗 | 四季与风雪、窗台罐、光线 | 推荐紧凑小窗默认候选 |
| 炉边 | 火、毛毯、扶手椅、闲暇动作 | 手动选择 |
| 书桌 | 专注手记、书、工作台、人物阅读 | 手动选择 |
| 院子 | 备柴、菜地、暖棚与雪天变化 | 手动选择 |

上述镜头属于**表现方案**，不是 01/03 已确认必须绘制五张独立大图。05 应评估复用同一母场景裁切、平移及少量特写层的办法，避免按五套独立作品估算。

### 3.2 人物走出选中的镜头

- **默认不自动追人、不突然切镜头【待选 U2，推荐】**：人物在院子里工作时，书桌镜头可以就是空书桌；这有助于专注氛围不被镜头切换干扰。
- UI 必须提供一句**真实状态描述**，例如「在院子里整理柴」「去泉屋提水」，免得玩家误以为人物消失。
- 允许一键回到全景或最近的镜头，但不修改世界位置、人物活动或工时。
- 氛围态可让人物出现在木屋里作**无生产演出**，就算真实人物冻结在院子，也不能写成其真的回屋或修好了设施。

## 4. 专注交互：可靠工具优先【以 02 定稿为准】

### 4.1 开始与进行中

- 预设：25/5、45/10、50/10、自定义、正向计时；开始、暂停、继续、延长、提前结束。
- 首次使用：一个显眼但克制的「开始专注」入口；后续可一键沿用上次预设和任务，**不选择任务也可开始**。
- 时间到只更新计时区、可选择柔和提示音；自动接下一轮取决于用户的既有设置。不会盖住正在工作的应用。
- 正在进行的现实任务名称可选展示；**默认仅在完整侧栏可见**，小窗和桌面角落可只显示类别或计时，保护隐私。
- 任务完成需要用户自己勾选，**番茄钟结束不自动宣布任务已完成**。
- 在输入框、文本编辑或外部应用具有焦点时，不劫持空格或数字等快捷键。

### 4.2 九个点与玻璃罐

- 当天获得几份就亮几个小点，总共九个；**不出现「距下一份剩余 X 分钟」**或“还差几份才能完成今天”。
- 现实时间 **00:00** 仅刷新当天九个点的显示；当前专注、45 分钟冷却、累计有效分钟及总份数按 02 继续。跨午夜不弹庆祝、不强迫重启。
- 得份即时写入现实手记、累计总份数与解锁；**场景玻璃罐中的云杉小球果可以等人物空闲再补放**，世界冻结期间的待摆放状态不能被伪装成已经做过的真实动作。
- 样式解锁无弹窗、无领取按钮；仅手记及样式列表有克制的“新增可选”提示。
- 现实累计时间、类别、任务书脊和纪念册与累计份数解锁的 24 件样式分开，不在 UI 混称为同一货币。

### 4.3 休眠恢复和异常断档

| 情形【规则来自 02 §3.4】 | 恢复界面 |
|---|---|
| 明确休眠、关机、应用退出后重新打开 | 计时会话为**已暂停**，保留已确认时间；可继续或结束。世界从冻结点恢复；**不能把离线时间算入有效专注** |
| 无法核实的异常断档 | 同样已暂停；在计时区附近出现**非模态、可忽略的选择**：「刚才 N 分钟算进去 / 不算」 |
| 选择计入无法核实的断档 | 保留用户确认的时间记录，按 02 的 10 分钟与 45 分钟等规则结算，**这一次最多补发一份**；世界仍不追赶 |
| 正常后台切窗、最小化但应用持续运行 | 不应仅因用户看不到画面就误判暂停；按 06 确认的实际运行与休眠判定记账 |

【交互建议】异常断档提示放在现实计时面板，不叠在木屋主场景上；用户选择前，该段时间标为“待确认”，不当作世界已推进。**不得把异常断档补算选项用于已确认休眠**。

### 4.4 休息期间

休息计时要清楚，但不催促玩家；角色只在合适的自主行为收尾后倾向喝茶、看雪、合书。人在户外主动操作时，休息结束也不强制把视图拉回木屋或重启下一轮计时。

## 5. 设施面板：查看状态、表达意向，而不是替角色干活

### 5.1 一套统一的轻量交互模型【已确认原则＋本轮 UI 提议】

鼠标悬停或键盘焦点给细微高亮；点击出现靠近该物件的**轻量状态卡**。结构统一：

    [设施名 · 当前真实状态]
    一句话说明（不是必须执行的清单）
    [可选意向 / 样式 / 查看详情]
    [关闭]

| 设施 | 可查询 | 允许的意向与操作 | 不能出现的旧版命令 |
|---|---|---|---|
| 柴堆／炉膛 | 柴真实数量、炉火状态、今日生活 | 仅查看 | 「现在去添柴」「多备柴」 |
| 地窖／粮架 | 粮、食材、罐头、库存状态 | 对有限罐头/燃油标「留着」 | 「现在做饭」「快去备粮」 |
| 工作台/待修设施 | 项目阶段、工时、缺哪些材料、等待原因 | 置顶项目（最多 3 件）、暂停/恢复 | 「消耗一份立刻推进一格」 |
| 菜地 | 格子作物、季节、下次预计动作 | 提出部分格子的种植偏好；至少 2 格仍由角色管 | 强制四格都按玩家种 |
| 窗台／书桌／窗帘 | 可用样式、纪念或收藏位状态 | 选择样式、查看纪念 | 直接变出未修好设施 |
| 仪器角/天气页 | 今日真实天气、允许的明日预报 | 查看和了解天气；后续可选角色观测表现 | 每日强制签到观测 |
| 床/椅子/唱片机 | 当前状态、可用设施功能 | 四个已确认小请求中符合条件的选项 | 白天反复睡到明天、未修好就播唱片 |
| 门 | 天气、行囊、路线、出门资格 | 准备并开始户外探索 | 无视暴雪规则直接传送 |

**小请求【已确认】**：今天早点歇、放唱片、泡茶、去窗边坐会儿；仅在条件可行时选择，择机执行，不插队打断必要生活，也不变成小游戏任务。

### 5.2 项目进度的可读性

- 一眼看到**当前阶段与下一阶段**，例如「窗缝：第二阶段 · 正在处理」；可查看本阶段材料与工作时间。
- 项目缺材料、天气不许、被用户暂停，要用**不同原因文字**明确区分；避免所有暂停都显示「等待」。
- 实物材料只在角色真实取用/开工阶段时扣账；UI 不出现与 02 相反的「立刻合成」按钮。
- 屋里短暂自然空闲可以出现，没有必要给每一分钟画一个生产进度条。

### 5.3 展示位和样式：三种状态必须讲清【交互建议】

| 状态 | 用户理解 | 合适的显示 |
|---|---|---|
| 已解锁／可直接使用 | 立刻生效的色温、声景，或已存在物件可选择的样式 | 可以点「应用」；按功能立即变更 |
| 已解锁／设施未就绪 | 例如窗帘样式已获得，但窗帘还没有挂上 | 保留拥有权，显示「待挂好窗帘」和相应项目；不伪装已修 |
| 已选／等待角色摆放 | 可用的实物样式已经选择，角色尚在忙 | 显示「想换成此款 · 待空闲」，当真实人物换好后消除 |

展示位格数【交互建议，具体数量待 05】以固定位置实现：书桌一角、窗台、炉上搁板、照片墙、书架纪念格；超出可见容量时转为手记收藏与替换选择，不自由摆家具、不制造无限房间资产。个人纪念书脊默认不展示现实任务名。

## 6. 独立氛围态：画面自由、世界暂停【已确认规则】

**纠正旧 04 v0.1 的关键冲突：不能在正常陪伴中「只自选天气画面、世界继续真实运转」**。如今只要选择非真实天气/季节/时段，就明确进入独立氛围态。

建议面板：

    [世界与氛围]
    ● 真实陪伴（当前：冬 · 第 12 日 · 小雪）
    ○ 独立氛围（世界暂停）
       季节 [冬]  天气 [大雪]  时段 [夜]
       [回到今天]

- 面板里始终说明**世界是否冻结**，而不是让用户通过勾一个独立的“世界暂停”开关自己猜。
- 调节风雪、炉火、生活声、音乐的**音量**不需要进入氛围态；基础声音层开局可用、音乐默认关。
- 氛围态可即时预览已经解锁的颜色、物件外观，**但实物换装在恢复真实陪伴后由角色实际完成**。
- 氛围态中的角色偶尔无生产闲暇动作仅为演出，不能在世界日志记为采集、施工、吃饭或真实走位。
- 退出独立氛围态后恢复冻结的真实日期、天气、库存与人物状态，不追算暂停经过的现实时间；份数仍按真实有效专注正常发放。

## 7. 户外、行囊、返家：防止把「切视图」误当作传送

### 7.1 从木屋出门【已确认规则】

木屋点门 → 行囊检查 → 开始出门过场 → 人物实际离开，进入户外直控。若正在有效专注，出门前**明确提示将暂停当前会话**，用户可以取消，而不是静默中断。

**暴风雪当天不能出门**：点门时可查看天气与缘由，出门入口不可用；不制造「被困必须解锁道具」的压力。大雪、冻雨虽可能影响院子劳动，按 02 仍允许尝试出门，界面仅给出温和的寒冷风险说明。

### 7.2 行囊面板【交互建议，数值完全来自 02】

    今日：小雪  [查看仪器/预报]
    路线：松林 / 溪谷 / 已解锁的冰湖
    干粮 [－] 数量 [＋]       家中余粮：真实数量
    柴捆 [－] 数量 [＋]       家中余柴：真实数量
    其他随身物品与背包 20 格
    提示：每种物资至少留够家中 3 天所需
    [开始出门]     [暂不出门]

- 只能带走高于**三天家中最低储备**的柴粮部分；若不可带应解释**「要给木屋留下三天用量」**，不是出现神秘灰按钮。
- 点击确认后才真实扣行囊里的家用柴粮、出门前压火所需的燃料；取消不能扣。
- 工具不做耐久进度；主动探索中普通柴粮单位时间产量不高于屋边自理，避免 UI 暗示刷柴粮是主目标。
- **首个 Web 可玩版先验证松林一处短途往返**；松林、溪谷、冰湖三张近处地区是早期完整范围，按 03 §0 分期，而不是要求原型一次全做。过夜、帐篷、远行、霜兽或旧版猎矛等**不放首版行囊入口**。

### 7.3 户外完整画面

    ┌───────────────────────────────────────────────────┐
    │ 体温/体力/生命（健康时轻淡，危险时明显）  时间/天气 │
    │                                                   │
    │                 户外区域地图                      │
    │                                                   │
    │ [歇一会儿] [吃一份干粮] [生火] [背包] [地图] [专注] │
    └───────────────────────────────────────────────────┘

- **时间按动作走（02 v3.2 §9.3）**：站着不动世界不走，没有户外速率选项。走一格、采集、歇息、吃干粮、生火各消耗配置里的游戏分钟；天色、家中炉火和饭点随这些分钟推进。按住 WASD 仍是一格一格走。
- WASD 与点击地面移动；点击资源点自动走过去采，点击或走近拾取掉落物。动物的交互另按 02 §9.6 分期。
- 常驻「歇一会儿」「吃一份干粮」「生火」；歇息回体力，在点着的篝火旁回体温。不可吃/不可生火时显示真实原因，不靠假按钮补资源。
- 背包、地图、手记开着时，UI 不发移动/采集/歇息/吃饭/生火指令，内核也拒绝动作；不积攒按键，关闭后重新输入。不计有效专注。
- 正常饭点有干粮自动吃一份；没有就不吃、不记缺餐，只是没得到体力恢复（02 §9.4）。
- 暴风雪天不允许开始出门，但出门后遇寒冷、大雪等仍要显示体温与安全退出方向；**不在户外为了气氛隐藏必要安全信息**。
- 傍晚可出现一次不抢焦点的「天色晚了」提示；夜晚仍可走，但到午夜依 02 昏倒回家，丢部分普通物资，藏品和特殊素材保留。
- **回家先走回区域的返家出口**，只有在出口或院门外才提供返家操作，路程由内核结算；到家入库换便服，专注不自动恢复。昏倒另按 02 §9.7；切木屋、镜头、专注画面都不能返家。

### 7.4 户外临时专注与返回【已确认规则】

人在野外点「打开专注」 → 世界和角色位置冻结 → 默认显示空木屋，可自选氛围场景/声音，开始现实专注并继续得份。此时高优先级入口是 **「返回野外（原地）」**。

- 专注计时结束不自动切回户外；在户外临时专注中**没有自动回家、自动探索或自动消耗背包**。
- 点击「返回野外」意味着从真实原地恢复户外直控；若此时现实专注仍在运行，需先暂停专注或明确结束当前有效计时，防止两种互斥状态同时运行。【交互建议：动作定义由 04 执行，遵守 02 的互斥原则】
- 小窗默认显示木屋专注状态，不开放户外实时 WASD 操作；想回户外要显式展开完整窗口。

## 8. 手记、任务与年册：事实同源、两栏分开【已确认规则】

### 8.1 手记导航【交互建议】

建议以少量主分区而非永远展示复杂六栏：**现实专注／世界日志／项目与收藏／世界年册**。世界日志内部可查看见闻，项目与收藏内部可看藏品、样式和慢事；最终分区数量交 04 原型可用性测试。

| 页面 | 主要内容 | 信息来源 |
|---|---|---|
| 现实专注 | 今日／本周、按类别或任务、时长/次数/份数、备注、非连续累计天数、个人书脊 | 真实已确认的专注记录 |
| 世界日志 | 当天真实天气、活动、修缮、种植、人物观察与第一次见闻 | 真实运行过的世界事件 |
| 项目与收藏 | 各阶段、材料、置顶/暂停、书籍、相片、场景固定展示位 | 实际拥有及项目状态 |
| 世界年册 | 年份性格、真实初雪、最长风雪、完成修缮、收成、去过的地点、俭天数 | 当世界年真实结束后汇总 |

- **用户主动打开才出现**，不弹窗推送；有新增日志可以给手记按钮一个静态、可忽略的小点。
- 现实任务名默认不出现在木屋书脊/桌面角落、小窗或导出的公开图片中；可选显示真实名称，提供隐藏与导出时脱敏选项。
- 世界日志第一人称可以温暖，但只写**发生过**的天气、行动、发现；现实统计并排出现也不能写成角色经历。
- 真实专注跨午夜：会话仍是一条，实时日统计按日期拆，份数按发放日记；不在 UI 创造第二个任务。
- 累计份数与世界年册不是同一套“通关进度”，不能互相换算。

### 8.2 视觉日记：不新增虚构情节

项目实物阶段、场景小球果、任务书脊、天气记录与照片墙是现有系统的不同表现。建议 06 使用同一事实数据源驱动画面和日志，避免「手记说修好收音机，场景还没修」的错位。对尚未放到可见展示位的收藏，手记可以显示“已带回，待摆放”，不假装已经放好。

## 9. 小窗、桌面后台与 macOS 后续【交互建议】

### 9.1 小窗优先服务真实工作

- 默认一个静谧的木屋镜头、细小的现实计时、必要的世界暂停/户外临时专注标志；鼠标悬停才出现暂停、结束、镜头、声音、展开。
- 目标是**不夺走用户在别的软件里输入的焦点**，不是保证每个 Web 浏览器都能无障碍系统级置顶。06 先验证浏览器支持再决定独立窗口、画中画或站内紧凑布局。
- 小窗显示角色可能不在当前取景框里；这并非错误。可提供一句短文字说明去向，不自动改变镜头。
- 小窗不要加入户外生命条、物品背包和修缮队列。真实仓库和长期进度在完整窗口查看。
- 可以隐藏任务名称；声音层单独可调，**不是只有进入氛围态才能静音或选声音**。

### 9.2 后台和菜单栏

正常陪伴收进后台（应用仍正常运行）世界与现实计时继续，户外直控切走则暂停直接操作。系统休眠或应用退出冻结世界并让计时恢复为已暂停；不能误认为锁屏/显示器熄灭必然进入休眠。

macOS 菜单栏版是后续形态：计时状态、开始/暂停/结束、声音、打开小窗/完整窗。正常运行时应复用同一世界状态机，**菜单栏本身不是第三个世界副本**。

## 10. 首次启动与渐进式教学【交互建议】

首次打开尽量直达一个有人、有炉火、能开始专注的木屋。

- **不强制注册账号、选任务或填角色档案**。可以稍后命名角色、查看前任记录。
- 首屏同时允许「开始专注」和「就这样看看」；两者都不会卡住游戏开始。
- 第一次点击设施只用一句话说明「你可以提出意向，他会在有空时做」，不再教旧版添柴/备粮命令。
- 第一次得份仅让九个点变化、罐子稍后有动作，不弹升级奖励窗。
- 第一次出门再解释行囊三天保留底线、恶劣天气、从原路回家；没出门的玩家不必看户外教程。
- 非必需剧情开场可以短且可跳过，不强制把玩家先送进野外完成教程。

## 11. 反馈、可访问性与输入保护

### 11.1 什么时候发声、出字

| 事件 | 声音 | 文字或画面 |
|---|---|---|
| 专注／休息结束 | 可关闭的轻提示音 | 计时状态安静变化 |
| 每日 00:00 | 无 | 九点无动画或轻变化，其他规则不重置 |
| 得份／解锁 | 无强制声 | 九点与手记变化，场景球果等角色有空再放 |
| 某阶段修缮完成 | 自然动作声 | 项目物件真实发生变化，手记可查看 |
| 观测天气／窗外小事 | 自然环境声 | 真实天气和世界日记；不弹奖励 |
| 暴风雪禁止出门 | 无报警 | 门状态明确解释，取消入口易找到 |
| 户外失温/威胁 | 环境和自然反馈 | 当前体温、体力、生命强调，可撤退 |
| 世界冻结模式 | 无 | 始终可辨的「氛围／户外暂停」说明 |

### 11.2 按键作用域

**原则**：只有拥有应用交互焦点、且不在输入框编辑时才触发游戏快捷键。小窗默认不监听全局快捷键；避免打断程序员的编辑器、终端和浏览器操作。

| 作用域 | 候选操作（交互初值） |
|---|---|
| 木屋完整窗口 | 空格开始/暂停专注，J 手记，数字键可切镜头（仅界面焦点可用） |
| 户外直控 | WASD 移动，E 交互，B 背包，M 地图，Esc 取消操作／关闭面板 |
| 独立氛围／户外临时专注 | 专注键与退出当前冻结模式的显式按钮 |
| 所有输入框 | 按键输入属于用户填写文字；不触发游戏快捷键 |

要求键盘可访问主要功能，并为像素图标提供可读文本、可调文字大小、必要对比度和减少闪烁／动效设置。提示不是只能靠颜色区分；有些声音可以单独关闭但不影响计时结算。

## 12. 设计前提与实现约束交 05／06

**05 美术与音频需要回答**：

- 室内母场景能否支持全景、雪窗、炉边、书桌、院子五种裁切？是否会造成镜头切换割裂？
- 角色常态习惯与延续性：看仪器、读同一本书、回头整理工具、坐窗边、杯子与书本是否可以用少量资产真实表现？
- 三档生活、五种炉火、四季天气、玻璃罐不同装满程度、前八件样式在小窗下是否仍可辨？
- 松林、溪谷、冰湖如何使用不同的声音与光照创造值得记住的体验，而不是三张资源表？
- 24 件样式若需要设施先修好，未就绪时的预览如何不伪造真实场景？

**06 技术与版本需要回答**：

- Web 计时在正常后台、休眠、异常挂起与恢复时的准确性；真正的休眠与无法确定的断档如何区分？
- 同一世界状态与真实事件日志驱动全景、小窗、手记、年册、项目阶段和收藏；防止分窗重复模拟和重入加份。
- Web 浏览器能否提供独立紧凑窗口、系统级置顶与不抢输入焦点？**先试再承诺**；桌面菜单栏能力仅到 macOS 阶段。
- 同时存在四种世界状态时，如何保证冻结不消耗、不增长、不隐性结算，返回真实状态不跳时？
- 户外开始前的行囊扣账、压火、出门/回家、户外临时专注及失败返回怎样做到同一事实状态？
- 首版的最小可用场景建议：可靠专注＋正常木屋自主生活＋低干扰回访＋真实双资源＋两件基础修缮＋前八档＋松林短途往返；不要求先做完整五镜头、全部区域及远行。

## 14. U1–U6 已确认的 UI 方向（允许根据原型微调）

**用户已在 2026-11-13 明确表示「先按你的规划来，你做设计和交互」**，因此下表六个推荐默认正式作为 **04 的初版 UI 方向**，交互是否舒适仍可用原型验证；不意味着已确认 05 的最终风格、美术资产或开发技术。02/03 已确认的 O1–O4、R1–R11 不再询问或修改。

| 编号 | 已确认的首版方案 | 可在原型中检验的替代 | 评估依据 |
|---|---|---|---|
| U1 计时可见性 | **小而淡地持续显示真实计时，可在设置里隐藏** | 默认只一根线、悬停才见时间 | 用户工作时抬眼能否快速看时间 |
| U2 特写空镜 | **空镜保持，不自动追人；附一句真实去向** | 人物离开就自动切到所在镜头 | 专注时镜头突然移动是否吸引注意力 |
| U3 完整窗口初始布局 | **全幅木屋画面，侧栏收起，一键展开** | 首次打开默认右栏展示任务与计时 | 首次开始专注是否足够容易 |
| U4 回访信息入口 | **主场景保持静谧，当前动作旁「看看今天」可选打开手记** | 边角自动出现一条近期事件摘要 | 回访能否自然感受到变化而不看日报 |
| U5 小窗默认镜头 | **默认雪窗特写；可手动换炉边，独立记住小窗镜头** | 和完整窗口同步全景 | 小屏幕中人物和雪窗是否清晰、是否过度裁切 |
| U6 手记导航 | **现实／世界／项目收藏／年册四个主分区** | 沿用旧版六个页签 | 重要功能是否易找、私密内容是否过度外露 |

以上 **U1–U6 的方向已确认**；六项中 U5 的雪窗为小窗初始镜头，完整窗默认全幅；用户可以自行切换。具体控件的位置、字号、动画和母场景仍交给原型与 05。**凡涉及改动 02/03 的实质机制仍需用户再次明确确认**；UI 方向确认不代表 04 现在整体定稿。

## 15. 与旧 04 v0.1 的重大纠偏

旧版中以下内容**不再沿用**：

- 点击炉火「添柴」、反复点床「睡到明天」、下拉「多备柴／多备粮」作为主操作；这些与自主生活原则冲突。
- 正常陪伴中随意更改天气外观而世界继续消耗；现在自选季节/天气/时段必须进入冻结的独立氛围态。
- 设置中默认凌晨 **4 点换日**；已定稿是现实时间 **00:00**，并且仅重置当日份数。04 不提供会使 02 算法失效的旧换日设置。
- 首版行囊中的帐篷、猎矛、野外过夜与旧式远行、霜兽等超前入口；它们属于后期或未采用内容。
- 把「切到木屋」误当作从野外真实返家；户外临时专注只是冻结当前位置并查看空木屋。
- 把「份已满」显示为要完成的每日任务；九个点仅是已经发生的真实记录。
- Web 原型保证系统置顶、macOS 菜单栏与不抢焦点等未经 06 验证的跨平台能力。

**状态提醒**：04 的 U1–U6 已确认；v1.2 和 05 v0.1 的镜头/视觉原型仍是测试方案，尚未在真实浏览器完成全面视效验收。01–03 均未修改，04/05 暂不标最终定稿。

## 16. UI 设计归属与交互原型的验收要求

**分工修订**：GPT 负责界面图片生成、视觉构图、分层资产试片与交互原型；Claude 负责游戏代码、真实灰盒、计时/世界引擎与工程测试。**交互设计双方有同等提案与评审权**，不应理解为 GPT 单方面决定或 Claude 仅可提工程建议。已定稿玩法的实质变化仍需用户确认。

**首版重点呈现五个连贯操作片段**：

1. **打开木屋**：画面优先，抬眼有炉火与当前角色状态；计时小而淡，侧栏默认收起。
2. **开始专注**：一次点击运行，九个点仅是记录；任务可选、无奖励倒计时；工作结束后仍在同一个世界。
3. **回访/手记**：不弹摘要，仅靠状态变化看出生活；主动点「看看今天」阅读已发生的世界日志，再切现实专注日志。
4. **切换氛围**：自选非真实天气/季节即冻结世界；界面有明确的「回到今天」；份数依现实专注继续。
5. **出门/户外临时专注**：出门先看行囊与天气、主动暂停原专注；户外可开专注冻结原地并显示空木屋；「返回野外」回原地而非传送回家。

**可操作概念原型**：[04 桌面陪伴交互演示（HTML）](原型/04_桌面陪伴_交互演示.html)，使用步骤与已验证范围见 [原型 README](原型/README.md)。演示实现了木屋全景、小窗、实时倒计时、手记四栏、氛围切换、松林出门及户外临时专注；它并不是完整游戏、游戏存档或正式美术资产。

**体验原型约束**：允许用示例数据、模拟按钮与占位图层演示视觉状态，但要明显标为「交互演示，不是真实存档/资源模拟」；原型里的演示时间与演示份数绝不能反向写进游戏正式存档。可使用单页 HTML 原型便于跨平台查看，05 后续按相同信息层级换成正式像素美术。

**供 Claude 的实现交接**：以 02 v3.0 的世界状态与现实计时作为唯一事实源；04 不能自建第二个游戏经济，不能凭 UI 演示模拟产生真实修缮进度；后台/休眠行为先由 06 验证再标为系统级承诺。

## 17. v1.2 原型优化：把确认的方案变成可用界面

**本轮基线**：`gpt/04-v1.2-ui-experience-20261113`，从 v1.1 UI 协作分支创建。可点击原型仍为同一路径 [04 桌面陪伴交互演示](原型/04_桌面陪伴_交互演示.html)，[使用说明与限制](原型/README.md) 一并更新。**此次不修改 01–03，U1–U6 方向不变。**

### 17.1 木屋：主画面要能自然被看一眼

- **调轻信息覆盖**：控制栏可见但不占视觉中心；当前动作卡更精简，世界日/季节/天气与现实计时各在其位置，避免把木屋变成统计看板。
- **优先让场景自己表达**：窗外雪只出现在窗景；炉火有低频、低幅的呼吸变化；室内没有不断飘动的装饰性雪粒。动态效果允许在系统减少动态效果时关闭。
- **可点的物件是细节入口**：炉膛/柴堆看真实生活状态，书桌/书架看项目/收藏，玻璃罐看现实专注手记。点击不下令角色做饭、添柴或立刻修缮；同一对象应有键盘可达的状态入口。
- **季节与时段的色彩变化**：原型用简化滤镜和环境表现验证氛围信息层级，不假装已有完整四季像素资产。真实场景的季节、天气、日夜版本由 05 制作。

### 17.2 小窗：不只是把完整窗缩小

- 默认雪窗特写；小窗内提供**不抢焦点的镜头切换**，可换到炉边，镜头偏好不覆盖完整窗口的全景偏好。
- 显示克制的专注计时、份数点、当前角色去向短句和返回完整窗的可靠入口；外部任务名称不默认出现在桌面角落。
- 完整窗可打开面板，小窗首先保护现实工作。切换尺寸不改变正在运行的专注，也不创建第二个计时器或世界副本。
- **原型已修复**小窗隐藏了“展开完整窗口”按钮的问题；真实 Web/桌面置顶、无焦点与独立窗口能力仍需 06 实测，当前单页小窗只是布局演示。

### 17.3 回访：数据先记录，场景由人物空闲时表达

- 演示「现实得份 → 当日九点与真实手记立即更新 → 等待角色空闲 → 玻璃罐里小球果增多」。**不能**让世界冻结时的现实专注直接变成“角色已经亲手放过球果”的假事件。
- 小生活事件在房间里留下有生命周期的可见痕迹（例如书桌旁新摆的热茶），并能在世界日记中看到对应条目。画面与手记必须以同一事实为来源；本次用演示按钮模拟，不代表程序已有真实事件管线。
- 不增加欢迎回来日报、不新增每日清单或提醒音；回访三层保持「2–3 秒看现状 → 多停留发现变化 → 自主翻手记」。
- 避免把角色等待摆放的微痕迹误写成食材、柴粮或施工项目产量。

### 17.4 四种状态交互一致性

- 独立氛围态可以展示非真实季节/天气/时段，清楚提示世界暂停；返回真实世界时不根据预览经历结算物资。
- 出门是明确的行囊流程；户外临时专注应冻结角色在原地，默认显示空木屋；**从户外临时专注只能返回野外原地，不能用切镜头“瞬移返家”**。
- 正常运行、菜单栏、小窗和完整窗的视图变化，与现实计时和世界推进状态分开，不产生重复计时。

**评审来源**：
- [Claude：04 设计意见 A1–A7/B1–B3](讨论记录/2026-11-13_04设计意见_Claude.md)
- [Claude：04 v1.2 实现方评审（22 条与三附表）](讨论记录/2026-11-13_04v1.2实现方评审_Claude.md)
- [GPT：双方评审整合决策与 Claude 交接](讨论记录/2026-11-13_04至06联合决策与交接_GPT.md)

**本节效力**：A1、A2、A3、A5、A6、A7 采用；A4 采用其发现的核心问题，但**不承诺直接扩大完整木屋母图**，先在灰盒量人物可见率并出远景试片。用户同意 06 灰盒与 05 并行、允许 `设计/原型/` 放可丢弃验证代码；06 正式实现归 Claude。旧 §2–18 如与本节具体交互冲突，以本节为 v1.3 设计初值。**尚未验证的数字、尺寸不能被说成实测结果。**

### 19.1 A1＋A5：以日常小窗为第一使用形态

1. **构图先行（采纳 A1）**：窗下书桌必须和雪窗、窗台玻璃罐位于**同一连续镜头**。雪窗默认裁切需要看见桌前人的**足够大的可识别姿态**，不是只看到半张窗帘；不能为了镜头出现人物而篡改角色作息。傍晚在炉边、去泉屋或林边时，空镜仍合理，显示简短真实去向。
2. **不追人（保留 U2/U5）**：不做默认自动追踪；未来可选「随他」镜头独立评估，不纳入首版。
3. **先测试真实尺寸（采纳 A5）**：分别把 **320×180、480×270** 的实际小窗贴在真实桌面截图上，另做 **1280×720** 的窗口高度测试。无论完整窗大小如何，专注计时和开始/暂停按钮**必须在可视区内**，不能因页面标题、导演台或画布最小高度而滚出屏幕。
4. **演示控制隔离**：游戏窗口只保留正常产品控件；模拟得份、切动作、快进等**导演工具在窗口外的开发调试侧栏**；分别保留「鼠标悬停 / 控件淡出」的实际截图。Web 小窗是否系统级置顶交 06 真机验证。
5. **优先量真实人物出现时间**：灰盒按正常作息累计 `actorVisibleInWindow / awakeTime` 和 `actorVisibleInWide / awakeTime`。没有灰盒数据之前不猜一个必须达成的百分比。

### 19.2 A2：专注只在一轮收尾时出现一行实际小结

- **专注进行中**不提醒份数、冷却和解锁。到一轮**实际结束或进入休息**的自然节点，出现**非模态、无声、自动退场**的一行小结；不替代角色动作卡常态，不要求点击领取。
- 内容来自**本轮真实事件**：`本轮 25 分钟 · 得 1 份 · 新样式：琥珀灯光`。没得份就只写本轮时长；没有新样式就不写样式。一次结算可能含多份，必须按结算事件集合汇总，**不能把“25 分钟”推断成必然得 1 份**。可通过手记找回。
- 小窗同样可见，但不要永久覆盖窗台或人物。开始下一轮、用户主动操作或短暂停留后自然收起，**不是固定要求动鼠标满 10 秒才消失**。不用弹窗或系统通知强调奖励。
- **A7 通知（采纳）**：独立设置「专注/休息结束时系统通知」，默认关闭。启用并授权后每次结束最多一条，只报告现实计时，不附带游戏内容、份数与样式；权限不可用时安静退化为界面状态更新。

### 19.3 A3：「看看今天」只在点击时原地打开近况卡

不直接跳转完整手记。动作状态旁点击后，**贴近木屋场景的轻量卡片**展开，点击空处或 Esc 收起，不抢现实工作窗口焦点。默认只放**最多 3–4 条重要世界事件**，可选「展开查看更多」查看当天最多 6 条，再进入手记。

近况卡信息顺序：
1. 当前人在何处/做什么（从真实 `actorState` 来）。
2. 当天到目前为止已发生的**真实**事件；02 §3.3 的前一天完整小结等次日醒来后才入账。
3. 柴粮各一条温和概况（用 02 生活档位/当前真实库存推导，必要时在设施详情查实际数量）。
4. **手头的事**：当前阶段及「打开项目面板」入口。
5. 最后才是「翻开手记」查看全部事实；**不增加日报推送、未读数或每天必点**。

### 19.4 A4：院外劳动时的人物如何被看见

- 先将状态映射分清：屋内 / 院子 / 近屋外远景可见 / 真正离开全景。**不把人在泉屋、林边的状态假装成他仍在窗台前。**
- **有条件采纳**：在 05 画一份「窗外或院门方向可见远处工作小人」的低成本分层试片，与「空景＋足迹＋远处环境声＋一行状态」并排比较。
- **不是必须加大母场景**：如果远景会挤压窗、人物、炉火三个关键锚点，宁可保留空景与去向说明；是否要制作更多院外背景以 06 的可见率数据和小窗/全景观看体验决定。
- 「人物大约一成时间不在全景」为 Claude 基于验算的**估计**，不是已验证的真实运营数据，不写入性能或体验验收门槛。

### 19.5 A6：05 美术与 06 工程统一资产契约

- 一份**可分层的母场景**产生全景、雪窗、炉边，使用像素对齐的固定裁切。当前原型 480×270 为初值；**不要将特写强制限制为恒定 2×**，但裁切应稳定、可配实际小窗像素比例。

**实际内容从结算事件生成**，示意两种情况：

- `本轮 25 分钟 · 得 1 份 · 新样式：琥珀灯光`
- `这一轮 25 分钟`（无新奖励时不评价“有没有得到份”，只保留时长）

这里的 1 份只是导演预设事件，而不是“25分钟必得”。正式 UI 必须接受任意合法的 `focusRoundCompleted(duration, sharesGranted[], stylesUnlocked[])` 事件集合，若跨轮/跨午夜等情况下得多份，准确汇总。系统通知与小结是两层独立机制：通知默认关，只报现实计时，不附带任何游戏奖励。

## 21. 05 G4 高清插画规格对齐（2026-11-14；只更新窗口/渲染，不改户外控制）
